# Git基操

会了Github，`Git`作为Github密不可分的一个工具，也是必须要学点基本操作的。

`Git`相当于Github这个网盘的客户端，但是他和普通的网盘不一样，Git能详细记录你每次提交到Github时修改的`每一行代码、每一个字符`。

## 仓库

我们早已经知道，Github上存项目的容器叫`仓库（Repo）`，实际上，仓库还可以分为`本地仓库`和`远程仓库`。

* `远程仓库`就是Github上面的仓库，也可以是`Gitlab`上面的仓库，这个就不用多说了吧。

* `本地仓库`就是你电脑上的一个仓库，理解起来也不难。打个比方，你把一个`远程仓库`克隆（git clone）到本地，那么本地就会出现这个项目的文件对吧？在这同时，`本地仓库`也就自动帮我们建立了。使用命令行工具打开这个文件夹，发现我们正处于`master`分支。

## git clone

这个命令可以说是最最熟悉了，白嫖别人代码的时候都这么用😋

但是我这里还是介绍一下这个命令：这个命令的作用是`远程仓库的代码克隆一份到本地，并在本地自动创建一个仓库`。

```shell
git clone 地址
```

`地址`可以是http/https地址，也可以是SSH地址。如果是自己的`远程仓库`，我墙裂推荐不要使用http/https地址，而是要使用SSH。

### git clone姿势：使用http克隆

如果是使用http方式克隆，那么：
* 如果你想推送更改到远程仓库，那么每次推送都要填写GitHub账号与Github token，非常麻烦。
* 克隆速度受中国🧱墙的影响，可能会很慢。

http/https克隆，适用于克隆/白嫖别人的项目仓库，对于自己的项目仓库，建议使用SSH克隆。

### git clone姿势：使用SSH克隆

好处：
* 推送远程更改时不用输入Github密码。
* 克隆与推送速度`极快`。
* 一次配置，就可以随意克隆这个GitHub账号上的所有`私有`和`公开`仓库，相当于在本地登录了一个Github账号一样，极度舒适～

第二点乃是重点，我相信你饱受中国高墙🧱之痛，无法下载Github上面的项目。但是如果你选择`SSH`下载，那速度将不受`任何限制`！直接无视GFW！

## git init

这个命令会在当前所在目录初始化一个`本地仓库`，并且会在本地生成`.git`文件夹。

每个本地仓库都会有这么一个文件夹的，不信你去看看（💦

## git remote

`Remote`，直接翻译成中文就是`远程`的意思，因此这个命令就是用来链接远程仓库的。

一般情况，`git init`初始化本地仓库后，就要在Github创建空的远程仓库；复制SSH远程链接，执行下面的命令：

```shell
git remote add origin 远程链接
```

此时本地仓库就链接到远程的空仓库了。

你也可以添加多个远程仓库，重复执行上面这条命令就得了。

命令中的`origin`是一个文件夹，用于存放远程仓库的链接；如果写移除远程仓库的链接，那么可以执行：

```shell
git remote remove origin
```

## 三件套：git add -> git commit -> git push

这三个命令，都是用来提交代码，但是他们各自的阶段作用不同。必须按照git add -> git commit -> git push三步走这种顺序进行提交。

### git add：暂存代码到本地仓库

“暂存”，即“`暂时存着`”，很好理解吧。

假设你修改了项目根目录下的README.md文件，可以使用`git add ./README.md`将更改暂存到仓库。

这条命令就这么简单。如果修改了很多文件，那是不是得一个个暂存呢？

```shell
git add .
```

直接用一个“`.`”代替，就可以把所有已修改过的文件拿来暂存。

### git commit：提交更改

`git commit`这条命令，用于提交更改。这条命令必须要指定`提交消息`，可以使用`-m`参数设置此次提交的消息。所以一般情况下，我们是这样使用这条命令的：

```shell
git commit -m “这里是提交消息，可以是int、float或者是string等”
```

`git commit`类似于代码实现的步骤，每个`提交消息`就是对这次修改的代码的步骤说明。

> 你可以这么理解：
> 你代码里写完几个关于注册新用户的函数，写完了，检查无误，你就可以使用一次*git commit*。

### git push origin 远程仓库分支名

没错，git push就是把本地所做的更改推送到远程仓库。`origin`就是我们`git remote`命令里面设置的那个名字啦～

如果你设置了默认分支，你也可以直接使用`git push`直接提交到仓库。

## git pull origin 远程仓库分支名

当远程代码有新的提交时，这个命令用来将远程代码同步到本地。

这个命令也很好理解，就是和`git push`命令相对的嘛。`push`是推送的意思，`pull`就是反过来。

你也可以直接使用`git pull`直接同步所有分支的代码到仓库。

## git branch

直接执行此命令就能列举出所有分支。

### git branch -D 分支名字

删除这个分支。D的意思就是`delete`（删除）的缩写。

## git checkout 新分支名

基于当前分支，新建一个新分支并且签出到这个新分支，或者签出到另外一个已有分支。

`签出`的意思就是让本地仓库`切换`到那个分支。无论这个分支存不存在，他都会切过去；没有这个分支他就会自动新建，有就直接切换。

那么，你在对这个分支做出修改之后，要怎么将这个本地分支推送到远程仓库呢？

很简单，就是

```shell
git push origin 新分支名字
```
