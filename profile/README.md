## Github咋用？
我知道你可能对Github不太熟悉，但是我是极力推荐你去学学Git操作的。
下面是Github功能的一些相关简介，助你速通Github：

### 分支（Branches）
每个仓库都有多个分支，主分支一般叫`master`或者叫`main`。现在一般都叫`main`，`master`叫法现逐渐变少，但很多老项目都还在，所以不会被淘汰，如果你看到此叫法请记住其与`main`一样都是仓库的主分支。

一般情况下，分支必须开两个以上，一个`main`。一个`dev`，以避免某些错误代码难以回滚。但我们比较懒，项目不算重要的都只开了`main`分支。

`dev`分支，顾名思义用于提交你写的代码，确认代码没问题后然后再把`dev`分支的代码合并（Merge）到`main`。分支。这是最基本的GitHub工作流。

### Fork
可以认为是把别人的仓库复制一份到自己的仓库中。

### Issue
顾名思义，你可以理解成Github仓库自带的一个可以提问题的评论区。可以用来反馈Bug或者其他什么的。

### Pull Request（简称PR）
在将别人的仓库Fork到自己账户后，在自己的仓库修改了某些代码，然后你希望让作者将你自己的代码Merge进去，那么就可以使用PR。

PR提交给作者后，作者会审查（Review）你的代码，如果采纳，作者就会将你的代码合并；如果有问题要修改，你的Github也会收到通知，提示你代码有问题需要修改。

### Actions
Github自带的一个功能，就是在你将代码提交到仓库之后执行一段脚本，执行脚本的服务器由Github免费提供。 

这个用途其实挺广的，比如自动把Vue项目打包出dist文件夹，并将dist文件夹里的东西移到`gh-pages`分支，这样每次提交新代码的时候，GitHub会自动帮我们打包代码并且部署到GitHub Pages。

### Discussions
不同于Issue，这个功能是GitHub近几年才加的，算是一个仓库里的小论坛。

### Wiki
顾名思义，如果仓库没有任何说明文档，说不定就放这里去了。

### Project
用来规划下一步项目的发展方向，仓库下一步要做什么等等。类似于To-Do、番茄清单之类的工具。
> 像我们这种没规划的人，我只能说：企业和大型开源项目还好，我们这种小项目就算了吧
